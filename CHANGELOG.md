# Changelog

English · [Русский](CHANGELOG.ru.md)

What changed in each release, newest first. `yami update` shows the section of the release it
offers (from CHANGELOG.ru.md when the interface is Russian); `tools/release.sh X.Y.Z` turns
«Unreleased» into the release in both files (and refuses while either is empty). Every line here
has its Russian line in CHANGELOG.ru.md: `tools/check.sh` checks that.

## Unreleased

- A brightness OSD (from yami-lite): changing the laptop backlight, by keys, `brightnessctl` or the firmware, shows its level like the volume does (settings → notifications, `osdBright`). It waits for the kernel's event instead of polling, so it costs nothing at idle and nothing at all without a backlight.
- Settings → wallpaper has a folder row: choose the folder the wallpaper picker shows (then the picker opens on it) or put it back to auto; a folder typed into the path field does the same, also without yami-files. When the «pixel cells» slider is above 1 (the mouse wheel moves it easily), the wallpaper picker says so at the bottom, with «as is» one click away: photos looked worse for no visible reason.
- The lock screen comes back by itself when the shell restarts or crashes while the screen is locked (an update, `yami restart`): before, niri kept the session locked with nothing to type the password into.
- The first-run setup opens with a small yami desktop that assembles itself out of palette cells (shown whole when animations are off) and ends with a summary of what was chosen; the last step greets you with a burst of sparks.
- Thumbnails (yami-files and the wallpaper picker share them) are written to a temporary file first, so a half-written picture can no longer be served from the cache when two programs make the same one or a write is cut off; leftovers go with the daily tidy.
- Ready templates (#31): the palette for Ghostty, Alacritty, WezTerm, Helix, Neovim, zathura, tmux, fuzzel, Vesktop and Equibop comes with the shell; settings → color → apps → «ready templates» adds one to your templates and shows the one line the app needs. Nothing is downloaded.
- A privacy light for the bar (`privacy`): it lights up while a program records the microphone, holds the camera or shares the screen, and a click says which one, mutes the microphone, stops a screen share or lowers the curtain. It watches only while it is on the bar; what it watches: `privacyMic`, `privacyCam`, `privacyScreen` (settings → bar → look; from the yami-lite fork). Apps you name in `castHide` (settings → windows, or `yami msg cast-hide` and a click on a window) turn black for the viewers of a screen share and stay as they are on your screen.
- The screen locks before any sleep, not only from the power menu: closing the lid, `systemctl suspend` or the system's own sleep timer wait until the lock screen is up (settings → system, `lockSleep`; from the yami-lite fork).
- Bluetooth without a terminal (#36): settings → bluetooth lists the connected, paired and nearby devices with their battery, and connects, disconnects, pairs and forgets them; the bar popup opens it with «all devices»; a `bt` desktop widget shows what is connected and how charged it is; paired headphones, speakers, keyboards and mice reconnect when Bluetooth turns on (`btReconnect`). All through BlueZ on D-Bus, nothing else to install.
- Updates and modules trust only what the installed version was built with: the release keys are part of the program, a tag is taken by its full name and the build runs from the very commit the checked tag names, so a branch called like a version cannot stand in for it. `yami report` also hides the weather city and the names of hidden drives.
- Ready binaries: on x86_64 with glibc 2.34 or newer a release installs signed, ready programs, with no compiler and in a few minutes, updates too; anywhere else, or with `--from-source`, it builds as before. Packages come from the same files: a `.deb` per program, `packaging/arch/PKGBUILD`, `packaging/fedora/yami.spec` and a Gentoo ebuild, and a package meets you with the first-run setup at the first login.
- The password typed into the first-run setup can no longer reach the screen or the install log: sudo asks it through a link only it can start. Installing modules from that window with a password also skipped the steps after the build, and no longer does.
- Your niri config stays yours in one more case: a config that started from niri's own and was edited since gets the include line and is no longer replaced. A link (stow, a dotfiles repository) stays a link when yami disconnects, and `yami niri disconnect` is respected by later updates.
- The Nix flake builds the shell and each module again after the split into repositories.
- Debian and Ubuntu get polkit from the installer (the package is called `polkitd` there), and a clean system no longer gets a compiler it does not need when the distribution has a recent niri.
- Everything of yami lives in one folder, `~/.config/yami`, like other shells have it: `shell.json` (was `~/.config/yami-shell.json`), `files.json` (was `~/.config/yami-files.json`), `scripts/` (was `modules/`), themes, templates and `niri/`. The old files move there by themselves.
- Your niri config stays yours: yami no longer replaces `~/.config/niri/config.kdl` but adds one include line at its top (`yami niri connect`, `yami niri disconnect`), and what you write below it wins. A missing config or niri's own starting one gets yami's starting config, the old file kept next to it. Settings → system → niri switches each part yami brings: its niri look, keys, window rules, colours, screens.
- With bash as the login shell (Arch and others) the shell no longer stays away after login: niri-session dropped `~/.local/bin` from the PATH, so neither the bar nor the keys like `Mod+Space` started. On CachyOS fish hid it.
- The first-run setup is part of the shell: a real step-by-step wizard, one topic per screen with big choices and previews, every setting of a topic one click away (language and style, colour, wallpaper, look, fonts, bar, dock, widgets, windows, keys, niri, notifications, system, services, games, modules), every button clickable, back and next at the bottom, the modules installed right there with the progress in view and the sudo password asked in the window. It opens by itself at the first login, also when the shell came as a package; `yami setup [step]` opens it again. The separate setup program is gone.
- Settings → animations: every group of panels (windows, bar popups, menus, notifications, widgets, dock) gets its own open and close pattern, duration and motion, with a live sample to click; notification cards now leave with an animation too (`anims`).
- Palette from the wallpaper (#31): a scheme picks how the picture's colour becomes the accent (tonal, vibrant, as in the picture, muted, monochrome); `yami palette show` lists every colour of the palette with its hex, `yami palette export NAME` keeps it as a theme.
- Your templates (#31) have an on/off switch each (`templatesOff`), and the full path of what they write is shown on a second line instead of being cut off.
- GTK keeps your own `gtk.css` (#31): yami's colours go into `yami.css` next to it, pulled in by one `@import` line, and GTK 4 apps such as Nautilus can keep their own look (settings → color → apps → «GTK 4 too», `themeGtk4`).
- cava follows the wallpaper palette again (#33): recolouring runs one at a time, so an older palette can no longer land last; setting `accent` by hand turns the palette from the wallpaper off, and settings say so. A theme chosen in cava's own config (`theme =`) no longer hides the gradient: the line is commented out with a semicolon, not deleted (#34, thanks to Im-onecane-btw).
- Settings show only what is installed: without yami-shot there is no screenshots tab, without yami-greet no login screen tab.
- A module is one file: `yami-files install` asks for the settings, lists what it will change and installs only after a yes.
- yami is now a shell and separate modules: yami-files, yami-view, yami-play, yami-shot, yami-greet and yami-niri each live in their own repository and work without the shell, so any of them can go into another setup. Each has a README that tells how to install, configure and theme it on its own, and the pixel look works without the shell's fonts. The shell's services (yami-agents) and the drawing library every module uses (yami-px) stay in this repository and come with the shell.
- A graphical first run: the install puts in only niri and the shell, and the first-run setup at the first login asks the language, the look and which modules to add. `yami setup` opens it again.
- Every module can look your way: a neutral look next to the pixel one, corners, shadows, fonts and each colour in `~/.config/yami/style.json`, and per module in `style.<module>.json`. Settings → look has the style of everything.
- yami-shot: the screenshot tool is its own program for any compositor with layer-shell.
- yami-view opens BMP, ICO, TGA and PNM pictures, and no longer lists TIFF and QOI files it could not open.
- yami-agents: the polkit window, passwords of encrypted drives, the screen-share picker and automount are one service that comes with the shell, each part switched on its own (`yami-agents status`). Its windows follow a new theme or language at once instead of keeping the look they started with.
- The installer's terminal side says what it is about to do in plain words and asks nothing else.
- yami no longer touches drivers: the NVIDIA profile and every trace of the old name are gone.
- Python is gone: recolouring other programs, the wallpaper and the cursors are part of the shell (`yami-shell recolor`), the installer no longer needs Python or Pillow, the developer tools are Rust (`yami-dev`).
- The installer in the terminal says up front how long it will take and how much disk it needs, shows what is compiling with a real progress bar and an estimate, and explains a failure in one sentence with what to do. Packages go in one transaction.
- Running the installer again over an installed yami is a repair: it keeps your modules and settings instead of quietly forgetting them. On a system without a login screen it says to start `niri-session`.
- Modules: the `apps`, `drives` and `tools` groups are gone. The terminal, btop and the night light come with the base; udisks2 and gvfs with yami-files and the shell; text and QR recognition with yami-shot. `niri-portals.conf` now follows what is installed.
- Updates are all or nothing: nothing is replaced until every part has built, an unchanged module is not rebuilt, and a run that fails half way puts programs and configs back by itself. `yami update rollback` returns programs and configs from the last rollback point (`yami update snapshots`).
- The setup window does not offer to replace another login manager by default, says why an install failed and can try again, works without sudo (doas), and restores its source tree if it is gone.
- The install counter is one anonymous request to a fixed address, in the background, once per machine; `DO_NOT_TRACK=1` turns it off. See docs/SECURITY.md.
- The bar at the bottom of the screen: settings → bar → look → «screen edge» (`barPos` = `bottom`). Popups, tray and window menus and the OSD open above it, a bottom dock stands above it, the line is drawn on the side of the desktop.

## 2.7.0

- Switch between players (#24): the bar and the music popup follow the player that started playing last, so a YouTube tab no longer pushes Spotify out; with several players the name in the popup is a button that switches to the next one (right click: back), and `yami msg media player` does it from a key. Play/pause, next and previous keys go to the player the bar shows.
- Keybindings in any layout: in Russian and other non-Latin layouts the keys with punctuation (`Mod+/`, `Mod+.`, `Mod+[`, `Mod+-`…) used to miss or hit the wrong bind, because niri looked at the symbol the current layout prints. yami-niri 26.04-yami.6 matches them by the key of your Latin layout, as letters already were; the power menu's letters work in any layout too. Active from the next login after the fork is rebuilt.
- The installer asks what to install: the components page has yami-files, yami-view, yami-play, the login screen, drives and phones, tools, games and the NVIDIA profile each on its own, `s` (or `--shell-only`) installs only niri and the shell, `--no-ID` / `--ID` set one from the command line. Only the chosen apps are built, only their packages installed. An update repeats the choice and takes out what was unticked (yami-files, yami-view, yami-play with their file associations).
- Restyle only what you want: a page of the installer (`--restyle`) and settings → color → apps list GTK, Qt and KDE, the cursor, kitty, fastfetch, btop, Firefox, MangoHud, foot, cava and starship; a program left out is not touched at all (kitty: the `include yami.conf` line goes, the rest of your `kitty.conf` stays). The key is `themeApps`; `appThemes` of 2.6 is carried over.
- yami keeps out of the drivers and the boot: the installer no longer sets NVIDIA variables for the whole session (`GBM_BACKEND`, `__GLX_VENDOR_LIBRARY_NAME`, `LIBVA_DRIVER_NAME`, `NVD_BACKEND`, `__GL_*`), never writes to `/etc/modprobe.d` or the initramfs config, no longer installs obs-gstreamer, puts no overrides on plymouth and gives yami-niri no capability behind your back (`yami-niri.sh status` says how to grant realtime). The `nvidia` component is one file now: niri's own profile against its VRAM growth. The next update rewrites `yami-local.kdl` without the variables; the initramfs files of 2.6 stay put, `yami doctor` names them with the command to remove them, `--uninstall` takes them out.
- Without yami-files the shell opens folders, the trash, mounted drives and `Mod+E` in your own file manager, «save as» of a screenshot saves into the screenshots folder, and the wallpaper picker hides its file buttons.
- The windows module of the bar (`tasks`, #28) works in any group: on the left and on the right it used to vanish, in the middle it stretched and pushed the modules after it against the right group. Now it is as wide as its windows and is centred with the rest of the middle, or sits right after the left group with `barCenterAlign` = `after-left` (where it was before); when the bar runs out of room it is the one module that narrows.
- Templates and recolouring you can see and trust (#27): settings → color → apps lists what came out of each of your templates (written, changed by hand with an «overwrite» button that keeps your edit as `*.bak-yami`, an unknown `{{colour}}`, no `yami-output` line, a target outside the allowed folders), and `yami templates` prints the same. A template with a typo in a colour is no longer written half-filled, an edit in `~/.config/yami/templates` renders at once instead of at the next palette change, hand-edit detection compares bytes and survives a moved home (`templates.json` keys are `~/…` now). Your own fastfetch `config.jsonc` is never replaced (yami's look goes to `yami.jsonc`), starship keeps the palette you chose, foot's include moved to the end of `foot.ini` with a `~/` path so your old colour lines no longer hide the palette, and unticking foot takes it out again. `yami msg ping` answers `pong`.
- The palette from the wallpaper is where you look for it (#26): settings → color has «palette from the wallpaper» right under the palettes, and `yami palette wallpaper` turns it on from a terminal (`yami palette` marks it). The accent comes from your picture again with every new one, and the whole palette follows it: background, panels, borders, the 16 terminal colours, every recoloured program and your templates.
- Clean pixel icons: the dock, the launcher and the bar no longer squeeze an icon into 16 px and dither it into four noisy tones. The icon is drawn large and averaged down to a grid of 16–30 cells (2 px cells in the dock), keeps 5–10 of its own colours with a dark outline and no dithering; «in palette tones» (`iconTint`) gives the old one-colour look, only clean. Plain icons are taken at the size they are drawn (a 48 px dock icon used to be a 16 px one blown up). yami-files, yami-view and yami-play have icons of their own, drawn in the palette.
- Your own icons and cursors: settings → look shows every installed icon set as a card with six apps drawn from it, and every cursor set with its arrow; a click switches the shell, yami's apps, GTK and Qt (and the cursor in niri and X11 apps). «Install your own set…» takes an archive or a folder (`yami icons add` / `yami cursor add` in a terminal) into `~/.local/share/icons`. yami no longer installs Papirus or picks an icon set for you: «auto» is the one your system already uses.

## 2.6.0

- Our own login screen instead of SDDM: yami-greet draws the lock screen's face (wallpaper under the veil, the big clock, the password field) inside niri, and greetd, a small daemon in Rust, checks the password and starts the session. No Qt, no QML, no theme files: it follows the shell by itself (palette, wallpaper, language, monitors and keyboard layouts, published to `/var/lib/yami-greet/look` on every change; `yami login sync` does it at once), remembers who logged in and the session, shows caps lock and the layout, asks second factors and password changes from PAM, offers sleep, reboot and power off, wipes a half-typed password after a minute and turns the screens off after two. If niri or yami-greet ever cannot start, greetd's text login takes that one boot. The installer switches an SDDM with the old yami theme over; by hand: `tools/greet-install.sh`.
- The login screen your way and sturdier: settings → system → login screen (`greet*` keys) picks its wallpaper (as on the desktop, the palette's pixel one, or the theme colour), the veil, the clock, the machine name, a user list or a name to type, the power buttons, when the screens go off and numlock; «preview» shows it over the desktop, and the tab, `yami login status` and `yami doctor` tell how its last start went (log in `/var/lib/yami-greet/log`). A quick login no longer counts as a failed start (two of those sent one boot to the text login), a start that shows no picture (a GPU driver still loading) is tried again, the hand-over to the session ends on a black frame instead of hanging on the last frame of the fade, and the console no longer flashes between the two. Works with OpenRC (Alpine, Gentoo) and runit (Void) as well as systemd: the login manager switches at the next boot, never in the running session.
- An update brings the new login screen along: from a terminal it asks right away, from the shell settings → updates gets one «install» button for it (greetd and yami-greet, SDDM is turned off and kept: `./install.sh --uninstall` brings it back); `yami doctor` and `yami update need` name it too.
- SDDM, which the login screen used before 2.6 (and the installer often installed), is turned off, not removed: it may belong to KDE. Once the new login screen has let you in, `yami doctor` says SDDM is unused and prints the one command that removes it with this distro's package manager.
- The installer is lighter and tidier: `install.sh` is only the entry (help, flags, the order of the steps), every job has its own module in `installer/`. The summary comes first and Enter installs what it shows (`c` walks through the choices); `sudo ./install.sh` is refused with a hint (it would install into root's home; the installer asks for the password itself); `slurp` and `xz` are no longer installed (nothing used them), `libcap` only with yami-niri; `--help` keeps the everyday flags apart from the rare ones.
- Hide a full battery (#21): settings → bar → look → «hide a full battery» (`batHideFull`) takes the `bat` module off the bar while the laptop is on power and not charging (full, or held at a charge limit).
- Security: the login screen's installer never writes as root through a link the greeter account could put in its own folder, and reuses the yami-greet the update has just built instead of building it again.
- Nix (#1): a flake with the package (the login screen included), a NixOS module (`programs.yami`: niri, the services, portals, fonts and tools, and greetd with yami-greet) and a Home Manager module (niri's config, settings, kitty, the default apps); CI builds it and evaluates the NixOS module on every push ([docs/PACKAGING.md](docs/PACKAGING.md#nix)). Started from TheCodedKid's work.
- Packagers: the Cargo feature `package-managed` hands updates to the package manager: no scheduled checks, the updates tab shows a note, `yami update` refuses and exits with 1; the shell and the login screen find yami-greet, its fonts and its session script inside the package's prefix (by TheCodedKid, #1).
- Brazilian Portuguese (`pt-BR`, by dznass-cmd, #20): the shell, yami-files, yami-view, yami-play, the login screen and the installer. Pick it in settings → system or let the system language choose it (`pt_BR.UTF-8` and `pt` work too); the language choice is shared by every app through yami-px, and the checks render every app in Portuguese.
- Phones, cameras and drives mount by themselves when they are plugged in (settings → services → drives and phones, `automount`, `automountOpen`), like in GNOME and KDE: USB sticks, external disks, memory cards, CDs and DVDs, disk images, Android phones in file transfer mode (MTP), cameras and phones in PTP mode, iPhones and iPads. The shell listens to udev without polling (a netlink socket that the kernel filters down to `block` and `usb` events) and mounts what the volume itself asks to be mounted, once per plug (a phone that is still locked is tried again for half a minute): a card says what was mounted and opens it. Encrypted drives ask for their password in yami-files instead. Nothing is mounted while the screen is locked: what was plugged in meanwhile mounts after the unlock.
- Fix: a phone with file transfer on did not show in yami-files until it was mounted by hand: phone and camera volumes have a USB device id that was taken for a disk's, so they were skipped. They show at once now, and a click mounts and opens them.
- yami-files: encrypted drives (LUKS, BitLocker) show as «encrypted», a click asks for the password (handed to `gio` over a pipe, never stored); «eject» unmounts, locks and powers the drive off.
- yami-files sidebar your way: drag places into your order, hide the ones you do not use (right click → hide, «show hidden» brings them back), fold the places, devices and network sections with a click on their title, name your bookmarks; a right click on any place or drive opens it in a new tab or in the other pane (it used to only open it in place), the middle button opens a tab. A long sidebar scrolls.
- yami-files never waits for a slow drive while drawing: the free space of devices and of the open folder is measured with the listing in the background (a hung network share used to freeze the window), and the trash is looked for on local disks only.
- Settings rebuilt: tabs in four groups (appearance, desktop, actions, system), every tab scrolls with the wheel, PageUp/PageDown, Home and End (a slider or number under the pointer is left alone while the page scrolls), the tab list scrolls too. Notifications have their own tab (cards, history, positions, the server); services gained «drives and phones». Each tab is one entry in a table with its draw function, search words and icon, so a new tab or row needs no other change.
- Blur under panels appears with the reveal (#18): it used to wait for the animation to end and then pop in; now it comes in during the first third of the reveal and goes the same way on close.
- Pixel tray (#19): settings → bar → look → «pixel tray» (`trayPixel`) redraws the tray icons on the bar and in the arrow's list in palette cells, like the dock and the launcher.
- Apps in the palette colours (#17): settings → color → apps: foot, cava (reloads at once) and starship follow the palette (`appThemes`), and your own templates in `~/.config/yami/templates` recolour any other app: `{{accent}}`, `{{bg}}`, `{{color4}}`… and a «yami-output:» line; written only under `~/.config`, `~/.local/share` and `~/.cache`, never over a file you changed.
- The shell's clickable areas end where their panel's visible part ends: a row scrolled under a list's header no longer catches the header's clicks.
- The shell idles in about half the memory with a picture wallpaper (11–13 MB instead of 19–21 at 1080p, more saved at 4K): once niri shows the wallpaper the shell keeps only a small copy for the settings preview and the widgets, and rebuilds the full picture when it needs it again (the lock screen and the stream curtain show at once and sharpen a moment later).
- The wallpaper no longer redraws whenever the pointer crosses the empty desktop (it took no clicks anyway), and «kanji on the wallpaper» applies at once.

## 2.5.1

- Fix: a fresh install got a shorter bar: the settings file the installer writes was taken for the pre-2.0 format, so the right side lost the battery, the power profile and the separators, and a `barRight` written by hand into such a file was dropped. Now only a file with the old keys is converted
- Fix: skwd-wall videos and Wallpaper Engine scenes (#3): yami now sees that skwd-wall draws them (its `skwd-wall-vk` layer) and no longer draws its own picture on that screen, which after a shell restart could cover the live wallpaper
- Docs in Russian: CHANGELOG, docs/CONFIG, docs/SECURITY and fork/README have Russian twins (`*.ru.md`), linked at the top of each file and from README.ru.md (which also gets back its missing «building the shell by hand» part); `tools/check.sh` keeps every pair in step (the same structure, code, links and anchors), so neither falls behind. With a Russian interface, settings → updates shows the release notes in Russian
- Media and sound are two popups (#10): the `media` module opens the player alone (cover, buttons, the equalizer, time; drag the position bar to seek, also in the media widget), `vol` the sound settings alone, with a choice of the microphone as well as the output when there are several; without a `media` module or a media widget (as on the default bar) the player stays at the bottom of the sound popup. Right click on the track pauses or plays, middle click skips to the next one; `yami open media` opens it from a key or the terminal
- Wallpaper picker (#11): settings → wallpaper → «pick an image…» opens a grid of thumbnails of your wallpaper folder (`~/Pictures/Wallpapers` by default, `wallDir`, «folder…» to change it), the palette's pixel wallpaper first; a click sets it and goes back to the settings, arrows and Enter work too. Thumbnails are made in the background only for the rows on screen and share yami-files' cache. «another file…» keeps the old file dialog; `yami open walls` (or a key you bind in settings → keys) opens the picker on its own
- Tray behind an arrow (#11): settings → bar → look → tray: `arrow` (`trayMode`) shows one arrow on the bar instead of every icon; it opens the tray apps as a list with their names, where clicks work as on the bar and an app's menu opens under its row. A dot on the arrow when an app asks for attention
- Compact temperature (#11): settings → bar → look → temperature: `compact` (`tempStyle`) draws the `temp` module as a small thermometer column and the number, about a third of its usual width
- Less work while idle: a panel whose new frame is the same as the last one is not sent to niri again (the bar redraws every second, its picture changes about once a minute), the sound state asks PipeWire only about what changed, the equalizer thread sleeps while nobody sees it and computes the spectrum once per frame, the settings file is compared only when the settings changed, font files are mapped once per process, and theme.py runs at a lower priority.
- Desk mode behaves like a desktop: a window gets focus on click and comes to the front with it (focus follows the mouse only in tiling now), so a title bar of a window behind no longer shows over the window in front, and every floating window has a resize corner at the bottom right (with niri's `prefer-no-csd` most apps had no edge to drag).
- Lite mode for weak and virtual machines (from a review: «extremely slow in a VM», a 15-year-old laptop locking up at login). Settings → look → «lite mode» (`lite`) turns off blur, the shell's and niri's animations and the translucency of inactive windows in one switch and leaves your settings as they were. A fresh install turns it on by itself in a VM, without GPU acceleration, on pre-2011 Intel graphics or with ≤ 4 GB of memory and ≤ 4 threads; `yami doctor` tells why it suggests it.
- One «pixel look» slider (asked in the same review: «a slider to set my pixelation lower»). Settings → look: smooth, softer, yami only, all pixel: the fonts of the shell, the apps and GTK/Qt, pixel icons and the cursor move together; the separate keys stay for fine tuning.
- The installer asks for the administrator password once: every root step goes through one root shell opened at the start (sudo or doas), with no credential cache left for build scripts. Packages missing from the distro's repositories are dropped from the batch instead of installing the rest one by one (on Alpine with doas that meant a password prompt per package). On a machine with less than 6 GB of memory or 4 threads the niri fork is off by default and cargo builds with as many jobs as the memory allows.
- yami-files looks for new drives, phones and network mounts only when the system's list of them changes (it used to start `lsblk` and `gio` every 4 seconds while a window was open), and an idle window ticks once a second; the D-Bus helper threads of the shell and yami-files no longer wake twice a second forever (zbus's `blocking` pool, held at 1.6).
- Caches tidy themselves: the thumbnail cache shared by yami-files and the wallpaper picker drops thumbnails not opened for 120 days and stays under 512 MB, and yami-play forgets resume positions of files not played for a year.
- Notification and OSD position (#8): settings → system → notifications: the cards go to any corner or the middle of the top or bottom edge (`notifPos`), the volume and brightness OSD to the bottom, the top or the centre (`osdPos`); cards keep clear of the bar and the dock.
- yami-view and yami-play tick once a second while nothing on screen is about to change (four times a second only while their panels are about to hide, faster only while something moves).
- Fix: `glass` set below 0.15 by hand (the slider stops there) made panels all but invisible, so their shadow and blur looked like broken frames (#8); lower values are raised to 0.15.
- The settings window moves by its header (#8): drag it anywhere on the screen; it opens in the middle again next time.
- Fix: Mod+F did nothing in desk mode (#8): it was `maximize-column`, which leaves floating windows alone; on the desk it now maximizes the window to the screen edges, and in tiling it still maximizes the column.
