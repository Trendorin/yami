# Справочник настроек

[English](CONFIG.md) · Русский

Всё, что меняет окно настроек, — это ключ в обычном JSON-файле; правка файла руками работает так
же и подхватывается на лету. Ключ с негодным значением возвращается к значению по умолчанию
(остальной файл сохраняется), неизвестные ключи пропускаются: `yami-shell config check` показывает
и то, и другое.

| Файл | Чей | Править руками |
|---|---|---|
| `~/.config/yami-shell.json` | шелла; yami-files, yami-view и `tools/theme.py` берут из него вид | да, на лету |
| `~/.config/yami-files.json` | yami-files | да (читается при запуске) |
| `~/.config/niri/config.kdl` | установщика | лучше нет: заменяется при переустановке |
| `~/.config/niri/user.kdl` | **твой** | да: подключается последним, побеждает всё выше |
| `~/.config/niri/yami-binds.kdl` | шелла (настройки → клавиши) | нет, переписывается |
| `~/.config/niri/yami-fx.kdl` | шелла (окна, вид, игры) | нет, переписывается |
| `~/.config/niri/yami-colors.kdl`, `yami-cursor.kdl` | `tools/theme.py` | нет, переписывается |
| `~/.config/niri/yami-outputs.kdl` | шелла (настройки → экраны) | нет, переписывается |
| `~/.config/niri/yami-local.kdl` | установщика (свои настройки niri этой машины; сейчас пустой) | нет |
| `/var/lib/yami-greet/look/` | шелла: то, из чего рисуется экран входа (`look.json`: палитра, язык, мониторы, раскладки; `wall.png`: обои), твоя с установки | нет, переписывается |
| `/var/lib/yami-greet/log/` | экрана входа: `greet.log` (его запуски, сообщения niri), `last` (как прошёл последний запуск) | нет, читать `yami login status` / `log` |
| `~/.local/state/yami/palette.json` | шелла: производная палитра, по которой красятся другие программы | нет |
| `~/.config/xdg-desktop-portal/niri-portals.conf` | шелла (настройки → службы); остаётся как есть, если больше не начинается с `# yami:` | через настройки |
| `~/.local/state/yami/install.json` | установщика и `tools/deploy.sh`: версия, коммит, источник, компоненты | нет |
| `~/.local/state/yami/update.json` | последняя проверка обновлений | нет |

## Терминал

`yami` — тот же бинарник, что и `yami-shell` (ссылка в `~/.local/bin`): без команды он печатает
справку, а не запускает шелл. `yami help <команда>` объясняет одну команду.

```sh
yami open settings:updates                # панель: launcher clipboard settings[:вкладка] power lock walls screenshot cal sound media net bt sys profile tray
yami palette | yami palette ash | yami palette '#3a9fd0' | yami palette wallpaper
yami wallpaper ~/Pictures/x.png           # без пути: пиксельные обои палитры
yami restart                              # перезапустить шелл (отказывается, пока в фокусе игра; --force)
yami status                               # шелл, портал, niri, последняя проверка обновлений
yami doctor                               # программы, службы D-Bus, конфиг: чего не хватает и чего это стоит
yami doctor games                         # ntsync, gamemode, MangoHud: что есть, одна команда для остального
yami report [-o FILE]                     # версии, doctor, журнал этой загрузки, конфиги в tar.gz для issue (секреты вычищены)
yami setup                                # окно настройки: вид, модули — поставить или убрать
yami ocr FILE                             # текст с картинки, то же распознавание, что «текст» в оверлее скриншота (нужен tesseract)
yami theme export FILE | import FILE|URL  # вид одним файлом: палитра, эффекты, шрифты, бар, виджеты, обои (никогда — команды); импортированная тема остаётся в твоих темах, ссылка — только https
yami theme save [NAME] | list | apply NAME | remove NAME   # свои темы в ~/.config/yami/themes (настройки → цвет → темы); save без имени называет тему по палитре
yami templates [force NAME]                # собрать свои шаблоны и показать, что вышло у каждого (force перезаписывает изменённый руками)
yami icons [NAME | auto | add PATH]        # наборы значков: список, сменить (auto — как в системе), поставить свой из архива или папки в ~/.local/share/icons
yami cursor [NAME | yami | system | size N | add PATH]   # курсоры: пиксельный yami, любой установленный набор, system (не трогать); размер; свой набор
yami export FILE | import FILE [--yes]    # все настройки одним файлом; user.kdl, свои клавиши и скрипты бара — только с --yes; перед импортом текущее состояние уходит в ~/.local/state/yami/before-import-*.json (вернуть: yami import этот файл --yes)
yami login sync                           # отдать экрану входа вид шелла сейчас (шелл делает это при каждой смене)
yami login status | log | preview         # экран входа: стоит ли, включён ли greetd, его последний запуск; его журнал; он поверх стола (пароль yami или Esc)
yami clean [--dry-run]                    # удалить кэш сборки (исходники yami-niri, target шелла: гигабайты); --force удаляет и дерево с твоей работой над патчами
yami version                              # каждая часть с установленным коммитом
yami update [check|apply|list|to X.Y.Z|rollback|status|log|need]
yami msg <command>                        # сырая команда шеллу (yami help msg)
yami-shell config list                    # каждый ключ = значение; * — то, что отличается от умолчания
yami-shell config get dockPins
yami-shell config set dockSide '"left"'   # ЗНАЧЕНИЕ — JSON; голое слово считается строкой
yami-shell config set animSpeed 0.7
yami-shell config reset dockSide          # один ключ — к умолчанию
yami-shell config reset                   # весь файл (старый сохраняется как .json.bak)
yami-shell config check                   # негодные значения и неизвестные ключи
yami-shell config kdl                     # что шелл пишет в yami-fx.kdl
yami-shell config lite-auto               # лёгкий режим, если машина слабая или виртуальная (так делает установщик)
yami-shell binds list | print | write     # сочетания клавиш
```

## Вид всех модулей

Каждый модуль читает `~/.config/yami/style.json`; шелл yami пишет этот файл из своих настроек
(настройки → вид), без шелла он твой. `~/.config/yami/style.<module>.json` (`files`
`view` `play` `shot` `agents` `setup`) — только то, чем отличается один модуль. Без них модуль
нейтрален и следует светлой или тёмной теме системы. `YAMI_STYLE` указывает другой файл на один
запуск. Файлы перечитываются при изменении.

| Ключ | Значения | Что значит |
|---|---|---|
| `preset` | `plain`, `yami` | основа: нейтральный или пиксельный вид; всё ниже её меняет |
| `accent`, `palette` | `#rrggbb`, id набора | цвет, из которого выводятся все тона |
| `light` | `true`, `false` | нет ключа — как в системе |
| `corners` | `notch`, `round`, `square` | углы панелей и кнопок |
| `radius` | пиксели | радиус углов панелей при `round` |
| `shadow` | `hard`, `soft`, `none` | тень под панелями |
| `reveal` | `fade`, `none`, `dither`, `scan`, `noise`, `wipe`, `blocks` | как появляются панели |
| `font` | семейство шрифта | пусто: `sans` при `plain`, Tiny5 при `yami` |
| `iconPixel`, `iconTheme` | `true`, `false`; имя набора | значки программ |
| `animations`, `animSpeed` | `true`, `false`; число | вкл или выкл, скорость |
| `wallpaperCmd` | команда с `{}` | «сделать обоями» вне шелла yami, например `swww img {}` |
| `lang` | `ru`, `en`, `pt-BR` | пусто — как в системе |
| `colors` | объект из `#rrggbb` | любой из `bg` `panel` `surface` `surfaceHi` `codeBg` `border` `dim` `accent` `deep` `glow` `bright` `selection` `text` `textDim` `textFaint` `onAccent` `textHi` `ok` `warn` |

## yami-shell.json

### Цвет и вид

| Ключ | По умолчанию | Значение |
|---|---|---|
| `palette` | `"blood"` | набор: `blood` `ash` `sakura` `amber` `venom` `ice` `dusk` |
| `accent` | `""` | свой акцент `#rrggbb`; пусто — акцент набора |
| `preset` | `"yami"` | стиль всех модулей: `yami` (пиксельный) или `plain` (нейтральный), [подробности](#вид-всех-модулей) |
| `corners`, `shadow` | `""` | `notch` `round` `square`; `hard` `soft` `none`; пусто — как у стиля |
| `radius` | `-1` | радиус углов в пикселях; `-1` — как у стиля |
| `colors` | `{}` | свои цвета поверх выведенных из акцента |
| `tint` | `1.0` | насколько графит берёт оттенок акцента |
| `glass` | `0.78` | непрозрачность панелей, 0.15 (стекло) … 1 (сплошная); меньшее поднимается до 0.15, иначе панели почти не видно |
| `lift` | `0.0` | яркость панелей: 0 почти чёрный графит, 1 заметно светлее |
| `inner` | `1.0` | непрозрачность карточек, графиков и полей внутри панелей |
| `dim` | `0.5` | затемнение за меню и настройками |
| `blurShell`, `blurTerm` | `true` | размытие niri под панелями шелла / терминалами |
| `animations` | `true` | байеровское проявление, движение панелей; false — выключено везде |
| `lite` | `false` | лёгкий режим для слабых и виртуальных машин (старые ноутбуки, виртуалки, отрисовка процессором): без размытия, без анимаций шелла и niri, неактивные окна непрозрачные; настройки выше остаются как есть и возвращаются, когда он выключен. Чистая установка включает его сама в виртуалке, без ускорения графики, на графике Intel до 2011 года или при ≤ 4 ГБ и ≤ 4 потоках (`config lite-auto`); `yami doctor` говорит почему |
| `animSpeed` | `1.0` | множитель длительности: 0.5 быстрее, 2 медленнее |
| `light` | `false` | светлая тема: бумага вместо графита, акцент углубляется, пока не станет читаемым; theme.py переключает с ней GTK (adw-gtk3, `prefer-light`), Qt, KDE, kitty, btop, курсор и светлый вариант значков |
| `reveal` | `"dither"` | как появляются панели: `dither` (Байер 4×4), `scan` (через строку), `noise`, `wipe` (диагональ с размытым краем), `blocks` (Байер, двойные клетки) |
| `revealGrain` | `1` | размер клетки проявления, 1–4 |
| `animClose` | `true` | панели закрываются обратным проявлением; выключено — исчезают сразу |
| `scanlines` | `false` | каждая вторая строка панелей шелла чуть темнее, как на старом мониторе |
| `wallpaper` | `""` | путь к своей картинке (PNG, JPEG, WebP); пусто — сгенерированные пиксельные обои |
| `wallDir` | `""` | папка, которую выбор обоев показывает сеткой (настройки → обои → выбрать, `yami open walls`; его кнопка «папка…» меняет её); пусто — `~/Pictures/Wallpapers` (или `wallpapers`), иначе папка текущих обоев, иначе `~/Pictures`. Миниатюры — в общем с yami-files кеше `~/.cache/yami/thumbs` |
| `wallFit` | `"fill"` | `fill`: закрыть экран, обрезав лишнее; `fit`: вся картинка, поля цветом фона |
| `wallPixel` | `1` | пиксельные клетки твоей картинки: 1 как есть, 2…8 → клетки 2, 3, 4, 6, 8, 12, 16 px |
| `wallTone` | `""` | окраска твоей картинки: `""` как есть, `tint` оттенки акцента, `palette` тона палитры с байеровским сглаживанием |
| `wallDim` | `0.0` | затемнить обои к цвету фона, 0…0.8 |
| `wallAccent` | `false` | брать акцент из твоей картинки, заново с каждой новой; за ним идёт вся палитра (фон, панели, рамки, 16 цветов терминала, все перекрашиваемые программы и шаблоны). Настройки → цвет → «палитра из обоев» или `yami palette wallpaper`; выбор цвета руками выключает это |
| `wallKanji` | `true` | знак 闇 в углу обоев |
| `wallSkwd` | `false` | обои берутся из [skwd-wall](https://github.com/liixini/skwd-wall): шелл читает то, что он пишет (`~/.cache/skwd-wall-v2/last-wallpaper.json`, `colors.json`; учитываются `SKWD_WALL_V2_CACHE` и `paths.cache`), и ничего не меняет в его настройках. На мониторе, где рисует skwd-wall (картинки — skwd-paper, видео и сцены — skwd-wall-vk, переходы; видно по его слою у niri), шелл прячет свои обои; иначе (режим «только выбор» skwd-wall) шелл рисует выбранную картинку сам своими клетками и тонами, видео или сцену — по кадру-превью. Экраны блокировки и входа показывают ту же картинку. `yami-fx.kdl` получает правило слоя, которое ставит фон обзора skwd-paper позади рабочих столов |
| `wallSkwdColors` | `true` | с `wallSkwd`: акцент — `primary` skwd-wall, а тема следует его фону (светлому или тёмному), так что палитра из его редактора тем перекрашивает весь райс |
| `iconTheme` | `""` | набор значков (настройки → вид → значки программ, `yami icons`): им пользуются шелл и программы yami, а GTK и Qt — когда они перекрашиваются; пусто — тот, что уже стоит в системе |
| `iconPixel` | `true` | значки программ чистым пиксель-артом: значок рисуется крупно и усредняется до сетки 16–30 клеток (в доке клетка 2 px), в 5–10 своих цветах с тёмной обводкой, без дизеринга |
| `iconTint` | `false` | пиксельные значки в четырёх тонах палитры вместо своих цветов |
| `fetchFull` | `false` | fastfetch с железом (ядро, пакеты, CPU, GPU, память, диск, дисплей); выключено — кто, ОС, wm, оболочка, терминал, время работы |
| `lang` | `""` | `ru`, `en`, `pt-BR` или пусто — по `LC_ALL`, `LC_MESSAGES`, затем `$LANG`; также принимаются `pt_BR.UTF-8` и `pt` |
| `themeApps` | все | какие чужие программы theme.py красит (настройки → цвет → программы, `--restyle` установщика): `gtk` (gtk.css, settings.ini, gsettings), `qt` (qt6ct, цветовая схема KDE, kdeglobals), `kitty` (цвета и шрифт; выключенный — строка `include yami.conf` уходит из `kitty.conf`), `fastfetch` (его `config.jsonc`, пока тот от yami; твой остаётся, а вид yami ложится рядом в `yami.jsonc`), `btop`, `firefox` (меню), `mangohud` (только конфиг, который написал yami), `foot` (`foot/yami-colors.ini` и строка `include=~/…` в конце `foot.ini` под своей `[main]`, так что она перекрывает цвета выше; для новых окон), `cava` (градиент в секции `[color]` её конфига, открытая cava перечитывает сразу), `starship` (таблица `[palettes.yami]`, которая перекрашивает и `red`, `green` и другие имена, и `palette = "yami"`, если ты не выбрал другую палитру). Невыбранную программу yami не трогает. До 2.6 включительно — `appThemes` (только foot, cava и starship), его читают один раз и переносят |

### Программы в цветах палитры

Рамки niri, экран входа и твои шаблоны всегда идут за палитрой; GTK, Qt и KDE, kitty, fastfetch,
btop, меню браузеров семейства Firefox, MangoHud, foot, cava и starship — когда они в `themeApps`
(все, пока ты не снимешь галочки). Для любой другой
программы напиши шаблон: файл в `~/.config/yami/templates` — это конфиг цветов программы, где стоят
`{{accent}}`, `{{bg}}`, `{{text}}`, `{{color0}}`…`{{color15}}` и другие имена палитры (`.strip`
убирает `#`, `.rgb` даёт `r, g, b`), плюс строка, куда его писать, и, если программа умеет
перечитывать, кому послать сигнал. Он собирается заново при каждой смене палитры и при любой
правке в папке шаблонов (шелл смотрит раз в 5 с). Пишется только в `~/.config`, `~/.local/share`
или `~/.cache`, никогда поверх файла, который ты менял руками, и вовсе не пишется, пока в нём есть
цвет, которого нет в палитре (опечатка сломала бы конфиг программы); файлы с окончанием `.md`
пропускаются.

Настройки → цвет → программы показывают, что вышло у каждого шаблона: записан, изменён руками
(кнопка «перезаписать» собирает его поверх твоей правки, а её оставляет как `*.bak-yami`), нет
такого цвета, нет строки `yami-output` или цель вне этих папок. В терминале `yami templates`
собирает их и печатает то же, `yami templates force ИМЯ` перезаписывает один; запись —
`~/.local/state/yami/restyle.json`.

```ini
# yami-output: ~/.config/mako/config
# yami-reload: USR1 mako
background-color={{bg}}
border-color={{accent}}
text-color={{text}}
```

### Шрифты

Настройки → вид → «пиксельность» двигает эти ключи, `iconPixel` и `cursor` (если там не твой набор курсоров) вместе, в четыре шага: гладко (системный sans и курсор везде), мягче (пиксельные только панели шелла), только yami (программы GTK и Qt гладкие, так ставит установщик) и всё пиксельное.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `fontShell` | `""` | шрифт шелла (любое семейство fontconfig); пусто — Tiny5. Непиксельные шрифты подгоняются под высоту заглавных Tiny5, чтобы раскладка держалась |
| `fontFiles`, `fontView` | `""` | yami-files / yami-view; пусто — как у шелла |
| `fontUi` | `""` | программы GTK/Qt: пусто — Tiny5 на своей сетке, `"sans"` — системный sans, или семейство (у установщика по умолчанию `"sans"`) |
| `fontPt` | `0` | размер непиксельного `fontUi`, pt; 0 — 11 |
| `fontSize` | `0` | размер пиксельного `fontUi`: 16, 24, 32 px или 0 — по высоте экрана |
| `fontMono` | `""` | моноширинный терминала (kitty) и Qt; пусто — Monocraft, иначе Terminess |
| `browserMenus` | `true` | браузеры семейства Firefox: контекстные меню, выпадающие списки и подсказки в палитре (больше ничего в браузере не трогается) |
| `browserFont` | `false` | и пиксельный шрифт в меню и панелях браузера (никогда — на страницах) |

### Бар

| Ключ | По умолчанию | Значение |
|---|---|---|

### Обновления

`yami update` и настройки → обновления работают в своём клоне, `~/.local/share/yami/src` (твоя
рабочая копия не трогается). Выпуск — самый новый тег `vX.Y.Z`; с `updateChannel` `main`
предлагается каждый коммит ветки. Установка запускает `install.sh --update` из нового дерева: он
пересобирает из исходников, сохраняет все настройки и не просит sudo; прежние бинарники уходят в
`~/.local/lib/yami/prev` для `yami update rollback`. `yami update list` показывает последние
восемь выпусков с их подписями, `yami update to X.Y.Z` собирает и ставит один из них (только то,
что проходит `updateVerify`). Перед переходом на более старую версию настройки копируются в
`~/.local/state/yami/settings-newer.json`; ключи, которые старая версия выбросила, возвращаются
оттуда при следующем переходе на версию не старее. Переход на целую версию пересобирает и
yami-niri на уровне этой версии (со следующего входа).

Обновление идёт без sudo. Когда компоненты, выбранные при установке (`tools`, `games`, …), хотят
пакеты, которых в системе нет — новая версия принесла возможность с программой-помощником, —
установщик пишет их в `~/.local/state/yami/packages-needed`; `yami update need` печатает одну
команду `sudo` (`--run` выполняет её), `yami doctor` и настройки → обновления показывают её тоже,
вкладка — с кнопкой **установить**, которая открывает её в терминале. Туда попадают только имена
пакетов, которые есть в репозиториях.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `updateCheck`, `updateEvery` | `true`, `24` | проверять самому каждые N часов (только проверка и карточка: установка — твой щелчок) |
| `updateChannel` | `"release"` | `release` (теги) или `main` (каждый коммит) |
| `updateVerify` | `"auto"` | `auto`: как только у установленной версии есть ключи в `keys/allowed_signers`, ставятся только теги, подписанные ими; `require`: никогда без подписи; `off`: без проверки |
| `updateRepo` | `""` | другой адрес репозитория; пусто — откуда была установка |

### Модули бара из скриптов

Исполняемый файл в `~/.config/yami/modules/<имя>` становится модулем бара `x:<имя>` (настройки →
бар показывают его вместе со встроенными). Скрипт печатает строку на каждое обновление — простой
текст или JSON; скрипт, который работает постоянно, шлёт строки потоком, а завершившийся
запускается снова через `interval` секунд (по умолчанию 10). Тот же скрипт может быть и виджетом
на столе (настройки → виджеты → скрипт), где `\n` в поле JSON `text` начинает новую строку; бар
показывает первую.

```sh
#!/bin/sh
# ~/.config/yami/modules/weather: значок 7×7, текст, цвет темы, щелчок, раз в 10 минут
t=$(curl -fs 'https://wttr.in/?format=%t' || echo '?')
printf '{"text":"%s","icon":"temp","color":"accent","click":"xdg-open https://wttr.in","interval":600}\n' "$t"
```

`color` — роль темы: `accent` `bright` `ok` `warn` `text` `dim`. `icon` — один из значков шелла
7×7, например `cpu` `ram` `temp` `net` `wifi` `bt` `bell` `clock` `cal` `music` `play` `power`
`bolt` `leaf` `moon` `sun` `gauge` `chart` `drop` `folder` `image` `camera` `lock` `user` `gear`.

### Виджеты

`widgetContrast` (по умолчанию `true`): виджеты без подложки следуют обоям под собой: на светлом
месте рисуются светлым вариантом темы (тёмный текст, более глубокий акцент), на тёмном — тёмным,
а у каждой буквы появляется жёсткая тень в пиксель шрифта противоположного тона, так что часы
читаются на ярких и пёстрых обоях. Замер идёт по подготовленной картинке обоев после смены обоев,
перемещения или изменения настроек.

`widgets` — список `{"id", "kind", "on", "x", "y", "source", "style", "anim", "size",
"color", "frame", "label", "seconds", "date", "text"}`: `kind` — `clock` `graph` `net` `media`
`cal` `weather` `script` `note`; графики берут `source` `cpu` `ram` `temp` `gpu` `swap` и
`style` `bars` `line` `blocks` `wave` `dots`; виджет `script` берёт имя файла скрипта в `source`. `x`/`y` равные -1 — место по умолчанию. Расставлять проще мышью:
настройки → виджеты, режим правки.

| `placesHidden`, `devsHidden` | `[]`, `[]` | скрытые места и устройства (ПКМ → скрыть; ПКМ → показать скрытые возвращает их) |
| `collapsed` | `[]` | свёрнутые разделы боковой панели: `places`, `devices`, `network` (щелчок по заголовку раздела) |
| `terminal` | `"kitty"` | «открыть терминал здесь» |
| `confirmTrash`, `singleClick`, `split` | `false` | |
| `width`, `height` | `1060`, `660` | размер окна при запуске |

Телефоны, камеры и сетевые ресурсы идут через gvfs (`gio mount`): пакеты `gvfs-mtp` (Android),
`gvfs-gphoto2` (камеры), `gvfs-afc` (iPhone) и `gvfs-smb` (общие папки Windows) добавляют
бэкенды; sftp, ftp и WebDAV есть в самом gvfs. Пароль спрашивается в окне и передаётся в `gio`
через канал; он не хранится. Монтирования ядра (cifs, nfs, sshfs, rclone) тоже видны.
Телефон появляется в боковой панели, как только включена передача файлов (yami-agents подключает его сам). Зашифрованный диск (LUKS, BitLocker) по щелчку спрашивает пароль
(`yami-files --unlock /dev/…` открывает это окно); открывает его udisks, а «извлечь» снова
запирает его перед выключением диска. ПКМ по месту или диску открывает его в новой вкладке или в
соседней панели.

Сочетания клавиш привычные (Ctrl+C/X/V, F2, Delete, Ctrl+T, Ctrl+L, Ctrl+H …) и совпадают по
положению клавиши, так что работают в любой раскладке.

## yami-play

`yami-play [FILE|DIR|URL…]` играет любой формат, который знает ffmpeg, через libmpv (пакет `mpv`,
загружается при запуске). Один файл открывает свою папку как плейлист в естественном порядке.
Позиция запоминается в `~/.local/state/yami/play/`, кадры сохраняются в папку Pictures.
Клавиши: пробел — пауза, ←/→ 5 с (Shift 1 с, Ctrl 30 с), ↑/↓ или колесо — громкость, F — на весь
экран, M — без звука, N/P — следующий/предыдущий, [ ] — скорость, A — звуковая дорожка, S —
субтитры, L — повтор, X — пиксельное масштабирование, C — сохранить кадр, `,` `.` — покадрово,
1…9 — переход на 10…90 %, I — сведения, Q — выход. `YAMI_PLAY_OPTS="hwdec=no,…"` передаёт
дополнительные опции mpv. Вид (палитра, язык, шрифт) — как у просмотрщика (`fontView`).

## yami-agents

`~/.config/yami/agents.json`, его же правят настройки → службы и `yami-agents enable|disable PART`.
`yami-agents status` покажет, что включено и кто делает работу.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `polkit` | `true` | окно пароля polkit; выключено — другой агент |
| `screencast` | `true` | выбор экрана и бэкенд портала (niri); выключено — окно GNOME |
| `automount` | `true` | флешки, карты памяти, диски CD/DVD, телефоны (Android, передача файлов), камеры и iPhone подключаются сами, как только их вставили |
| `automountOpen` | `false` | подключённое сразу открывается; выключено — уведомление с кнопкой «открыть» |
