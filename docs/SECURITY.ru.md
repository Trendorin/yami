# Заметки о безопасности

[English](SECURITY.md) · Русский

Чему yami доверяет, что открывает наружу и что проверено (аудиты 2026-11-03, 2026-11-04, 2026-11-07 и 2026-11-09).

## Как сообщить об уязвимости

Пожалуйста, не пишите о ней в открытых задачах: отправьте [закрытый отчёт на GitHub](https://github.com/Trendorin/yami/security/advisories/new). Его видит только автор, ответ придёт там же, а подробности публикуются после выпуска исправления.

## Репозиторий

- Историю `main` и ветки `stats` нельзя переписать, сами ветки нельзя удалить, теги выпусков `v*` нельзя передвинуть или удалить (правила репозитория без исключений, в том числе для владельца): тег выпуска всегда указывает на тот коммит, что был подписан.
- CI работает с токеном только на чтение и не видит секретов в запросах на слияние; первый запрос на слияние от нового человека не запускает ни одной проверки, пока автор его не одобрит. Сторонние шаги CI закреплены на коммите; Dependabot их обновляет и сообщает об уязвимых крейтах.
- Это защищает репозиторий; то, что ставится, по-прежнему проверяется подписью выпуска (см. «Обновления»).

## Поверхности

| Поверхность | Кто может до неё дотянуться | Защита |
|---|---|---|
| `$XDG_RUNTIME_DIR/yami-shell.sock` (IPC) | процессы того же пользователя | права сокета 0600, UID собеседника проверяется (`SO_PEERCRED`), читается одна строка ≤ 4 КБ с таймаутом 2 с; команды только открывают панели, блокируют, делают скриншоты или выходят: ни одна не запускает программу |
| агент polkit (`/org/yami/PolkitAgent`, системная шина) | polkitd | вызовы от кого-либо, кроме владельца `org.freedesktop.PolicyKit1`, отклоняются, так что никакой другой процесс не может вызвать окно пароля; пароль уходит только в `polkit-agent-helper-1` (сокет polkit, иначе setuid-обёртка `/run/wrappers/bin` на NixOS, пути дистрибутивов, потом `PATH`) и стирается из памяти после использования |
| экран блокировки | место за компьютером | `ext-session-lock`: если шелл умрёт, niri держит экран заблокированным. Пароль проверяет PAM (только `pam_unix`, свой файл службы в `~/.local/state/yami/pam`, так что faillock не блокирует учётную запись из-за опечаток; пользователь не из `/etc/passwd` — LDAP, SSSD, systemd-homed — идёт через системную службу `system-local-login` или `login`), копии стираются после проверки; монитор, подключённый во время блокировки, получает свою поверхность блокировки |
| экран входа (yami-greet) | место за компьютером; устанавливавший пользователь (папка вида) | PAM и сеанс ведёт greetd (root); yami-greet работает от непривилегированного пользователя greetd в своём niri, лежит от root в `/usr/local/bin` и отдаёт пароль только greetd (`$GREETD_SOCK`): запрос собирается вручную и затирается после отправки. Папка вида `/var/lib/yami-greet/look` — пользователя: `look.json` и `wall.png` разбираются как недоверенные данные (пределы размера и картинки), а конфиг niri экрана входа берёт из неё только значения мониторов и раскладок, прошедшие белый список символов, — никаких команд и биндов. Сеансы — только из `wayland-sessions` системных каталогов данных. yami-greet не даёт снять с себя дамп, не получает новых прав и не пишет core-файл; файлы вида открываются только как обычные файлы ограниченного размера и никогда по ссылке (FIFO или устройство там его не подвесят, ссылка не заставит прочесть файл, недоступный пользователю); без папки выполнения от logind он делает свою (`mktemp`, 0700), никогда не угадываемое имя. Передача сеансу заканчивается чёрным кадром, в терминал ничего не печатается. Если niri или yami-greet не запускаются, один вход отдаётся текстовому приветствию greetd (`greet-session`); его журнал `/var/lib/yami-greet/log` не хранит паролей и набранных имён |
| шторка приватности (Mod+Shift+H) | трансляции экрана через xdg-desktop-portal (OBS PipeWire, Discord, браузеры) | на yami-niri ≥ `.4` слой, который рисуется только в трансляции (`show-only-in`), закрывает экран застывшим кадром — размытым (или пикселями по 24 px, или обоями); панели шелла, открытые тем временем, получают новую шторку поверх; с `.5` закрыто и отдельно показанное окно (своей частью шторки). Переключатель Alt+Tab в niri рисуется поверх всех слоёв и не закрывается; захват через wlr-screencopy (grim, OBS wlrobs) не закрывается. На другом niri вместо этого закрываются окна |
| бэкенды порталов (FileChooser, ScreenCast, FileManager1) | xdg-desktop-portal, программы того же пользователя на сессионной шине | программы в песочнице доходят до них только через фронтенд портала; выбор экрана — окно yami-agents; имена файлов, которые программа предлагает или просит (`current_name`, «сохранить несколько файлов»), сводятся к одному имени, и пути, на которые фронтенд даёт права, не выходят из выбранной пользователем папки |
| уведомления, трей | программы того же пользователя | рисуются как текст и декодированные картинки (декодеры на чистом Rust); сырые картинки проверяются по размеру до выделения памяти (≤ 1024², без переполнения целых), файлы, названные программой (`image-path`, обложка `file://`), читаются только обычные и ≤ 16 МБ, декодеры работают с ограничением 64 МБ; не больше 64 значков трея; заголовок, текст и действия ограничены (512 Б, 8 КБ, 8); ответы, действия и `NotificationClosed` уходят только соединению, приславшему уведомление, и только оно может его заменить или закрыть; ничего не выполняется, кроме действия, на которое нажал пользователь; каждую службу можно выключить (настройки → службы) |
| обложки альбомов | плеер (MPRIS `artUrl`) | `curl -q` (без пользовательского curlrc), только http(s), после переадресаций только https, ≤ 3 переадресаций, ≤ 16 МБ, 8 с; выключенный `mediaArtNet` держит шелл без сети |
| тексты песен | плеер (MPRIS `xesam:asText`, `xesam:url`), lrclib.net | текст плеера и `.lrc`/`.txt` рядом с локальным треком читаются как текст (обычные файлы, ≤ 256 КБ); lrclib.net получает исполнителя, название и длительность через `curl -q`, только https, 8 с, ≤ 2 МБ, ответ разбирается как JSON и показывается текстом; спрашивается, только пока всплывашка музыки показывает текст; выключенный `lyricsNet` держит это без сети |
| погода | open-meteo.com | уходят только город (или координаты) из `weatherCity` и единицы, через `curl -q`, только https (и после переадресаций), 10 с, ≤ 1 МБ; ответ разбирается как JSON и показывается числами и текстом; спрашивается, только пока виден модуль или виджет `weather`, а с пустым `weatherCity` — никогда |
| файловый менеджер | съёмные носители | корзина на съёмном диске считается корзиной, только если она сама и её `files` — настоящие папки пользователя, а не ссылки: диск, корзина которого указывает на домашнюю папку, не показывается и не очищается; `.trashinfo` там не может указывать за пределы этого диска (`..` и абсолютные пути в другие места отклоняются); архивы идут через `bsdtar`, который отклоняет абсолютные пути и `..` (имена сжимаемых файлов идут после `--` и не читаются как ключи); FileManager1 открывает не больше 16 папок за вызов |
| автоподключение (`automount`) | любой, кто вставил устройство | только тома, которые udisks/gvfs помечают для автоподключения (съёмные диски, телефоны, камеры; разделы внутренних дисков — никогда), подключают они сами со своими опциями (`nosuid`, `nodev`); при заблокированном экране ничего не подключается (метка шелла yami или `LockedHint` в logind для других экранов блокировки): вставленное тогда ждёт разблокировки; зашифрованные диски только спрашивают пароль в yami-agents, который отдаёт его `udisksctl` через канал и нигде не хранит |
| просмотрщик картинок | файлы, которые ты открываешь | анимации ограничены 600 кадрами и 1 ГБ декодированных кадров |
| выбор обоев | картинки папки обоев | только обычные нескрытые файлы png/jpg/webp, не больше 500 из папки; декод в фоновой нити шелла с теми же пределами, что у yami-files (больше 40 Мпикс не декодируется, потолок 256 МБ), миниатюры в кеше `~/.cache/yami/thumbs`; в памяти — только видимые строки, при закрытии всё отпускается |
| открытие файлов | щелчки пользователя | строки `Exec=` разбираются в argv без оболочки, имена файлов никогда не подставляются в командную строку |
| свои сочетания клавиш | пользователь (настройки → клавиши) | запускаются niri через `sh -c`, как любой `spawn-sh` в niri |
| скрипты бара (`~/.config/yami/scripts`) | собственные исполняемые файлы пользователя | работают, только пока их модуль в баре, каждый в своей группе процессов во главе с маленьким `sh`: вся группа (скрипт и то, что он запустил) получает SIGTERM, когда модуль убирают из бара или шелл умирает (`PR_SET_PDEATHSIG` у лидера); вывод читается построчно (строка длиннее 4 КБ пропускается); `click` модуля запускается через `sh -c`, как своя клавиша |
| лаунчер `>` и `/` | то, что набирает пользователь | `>` запускает набранную команду в терминале (как если набрать её там); `/` только обходит домашнюю папку (без скрытых папок, без папок-ссылок, ≤ 8 уровней, ≤ 60 000 записей) и открывает выбранное через `xdg-open` |
| ответ из уведомления | программа, приславшая уведомление | текст уходит только как `NotificationReplied` этому уведомлению; поле стирается после отправки, ничего не хранится и не копируется |
| `yami theme import` | файл или https-ссылка от кого угодно | ссылка скачивается через `curl -q`, только https (и после переадресаций), ≤ 3 переадресаций, ≤ 64 МБ, 30 с, в новую папку 0700 и должна быть темой (`kind: theme`), никогда — полным файлом; только ключи вида (палитра, эффекты, шрифты, бар, виджеты, вид дока, отступы, курсор) и картинка обоев (сохраняется обычным файлом в `~/.local/share/yami/wallpapers`, имя очищено от пути); никогда — сочетания клавиш, команды, скрипты или источник обновлений. | `yami report` | ты, для issue | ничего не отправляется; строки с именами пароля, токена, секрета или ключа очищаются, путь к дому, имя пользователя и хоста заменяются, место, где ты живёшь (ночной свет, погода), твои серверы и имена устройств скрываются; архив стоит прочитать, прежде чем прикладывать |
| процессы шелла | настройки пользователя | wlsunset (ночной свет) запускается с фиксированными аргументами; у него и у помощников музыки, звука и визуализатора (playerctl, pactl, parec) стоит `PR_SET_PDEATHSIG`, так что ни один не переживёт шелл или его перезапуск |

## Установщик

- Работает от пользователя; `sudo`/`doas` — только для пакетов, служб и экрана входа. Больше ничего
  в системе: ни окружения драйвера, ни
  опций модуля, ни initramfs, ни capability на бинарнике (realtime-приоритет yami-niri — решение
  пользователя, `yami-niri.sh status` подскажет, как).
- Модули: каждый берётся по тегу из `modules.lock`, и его подпись сверяется с
  `keys/allowed_signers` установленной версии, прежде чем что-либо собирается. Тег берётся по
  полному имени, а сборка идёт из коммита, на который указывает проверенный тег, так что
  одноимённая ветка его не подменит.
- Загрузки: сам репозиторий (git по HTTPS), rustup, когда Rust дистрибутива слишком старый
  (только `https`, TLS 1.2+), Monocraft закреплённой версии со сверкой SHA-256. niri и smithay
  скачиваются на закреплённых коммитах, патчи берутся из этого репозитория.
- Один root-сеанс на все шаги с правами (один пароль); его каналы доступны процессам самого
  пользователя через `/proc`, поэтому он живёт только эти шаги, а они все идут до сборки: он
  закрывается раньше, чем cargo запускает сборочные скрипты крейтов.
- `bash <(curl …)` запускает код из сети: прочитай сначала `install.sh`, если не доверяешь
  источнику; `--dry-run` показывает план.

## Обновления

- Обновлятор работает в своём клоне (`~/.local/share/yami/src`), запускает git без вопросов
  (`GIT_TERMINAL_PROMPT=0`, хуки выключены) и с таймаутом на зависание; теги скачиваются без
  `--force`, так что тег, переписанный на сервере, не заменяет уже виденный.
- Подписи: доверенные ключи — `keys/allowed_signers` уже установленной версии, вшитые в саму
  программу (доверие при первой установке, как и сама установка), так что от содержимого клона
  обновлятора они не зависят. Как только в этом файле есть ключи, выпуск с
  неподписанным тегом или подписанный другим ключом отклоняется (`updateVerify` `auto`), так что
  тот, кто получил доступ на запись в репозиторий, всё равно не сможет выпустить обновление.
  Подпись засчитывается только с совпавшим principal (`gpg.minTrustLevel=fully`, и «No principal
  matched» отклоняется, даже где старый git завершился бы с 0). Выпуски делаются
  `tools/release.sh`, который подписывает каждый свой тег (шелла, каждого модуля, yami-px) и
  контрольные суммы и останавливается, если хоть одна подпись не сходится с этим файлом.
- Готовые бинарники: архив выпуска берётся, только если `SHA256SUMS.sig` сходится с
  `keys/allowed_signers` устанавливаемого тега (пространство имён `yami-release`), а архив
  совпадает со своей строкой в `SHA256SUMS`; без подписи или с чужой установка останавливается, ничего не изменив.
- Установка: `install.sh --update` из нового дерева от пользователя, без sudo; прежние бинарники
  сохраняются для `yami update rollback`. Игра в фокусе откладывает перезапуск шелла.
- Закрытый или открытый репозиторий: тот же HTTPS-адрес. Пока он закрыт, git использует
  помощник учётных данных пользователя (`gh auth login`); открытие репозитория не требует
  изменений у клиентов.

## Известные компромиссы

- Папка вида экрана входа `/var/lib/yami-greet/look` принадлежит устанавливавшему пользователю,
  чтобы палитра и обои следовали за шеллом; её содержимое меняет только то, как выглядит экран
  входа. На машине, общей с недоверенными пользователями, отдай её root: экран входа сохранит
  вид, какой у него есть.
- Файл службы PAM экрана блокировки лежит в каталоге состояния пользователя: процесс от имени
  пользователя мог бы его ослабить, но такой процесс и так управляет сессией.
- История буфера обмена (cliphist) пропускает записи, которые менеджеры паролей помечают как
  секретные (`x-kde-passwordManagerHint`, `CLIPBOARD_STATE=sensitive` у wl-clipboard); всё
  остальное скопированное хранится до удаления (`Mod+V`, `Del`). Закреплённое — копии в
  `~/.local/share/yami-clip` (0700); превью картинок декодируются только в памяти.

## Счётчик установок

У yami нет телеметрии: шелл никогда ничего не сообщает, а обновления — это `git fetch` открытого
репозитория. Значок «installs» в README считает одно: когда установка закончилась, установщик **один раз на
машину** запрашивает у GitHub однострочный файл `yami-installs.txt` с постоянного выпуска `installs` и выбрасывает
ответ. GitHub считает скачивания файлов выпусков; `.github/workflows/stats.yml` раз в день складывает эти
числа и пишет значок в ветку `stats`.

- Запрос ничего не несёт о тебе или машине: ни идентификатора, ни версии, ни настроек, неизменный
  User-Agent `yami`. GitHub видит то же, что при любой загрузке (твой IP-адрес), как и при `git clone`,
  который установщик и так делает.
- Он идёт в фоне с коротким тайм-аутом: задержать установку или сломать её он не может.
- Один раз — значит один раз: метка `~/.local/state/yami/counted` делает последующие обновления
  тихими. Машины, установленные до счётчика, учитываются один раз, при следующем обновлении. Неудачная установка не считается.
- Отказаться: `install.sh --no-count`, `YAMI_NO_COUNT=1` или общепринятый `DO_NOT_TRACK=1` в окружении: запроса не будет
  вовсе (в CI и при `--dry-run` тоже пропускается). Создать файл-метку вручную — то же самое.
- Он считает установки, а не людей и не активные машины: переустановка после удаления
  `~/.local/state/yami` считается снова, удаление не вычитается.
